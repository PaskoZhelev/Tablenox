# Tablenox — context for LLM assistants

Read this first. It covers what the app is, how the code is organised and the rules that are easy to break. For more detail, see [README.md](README.md) (features and shortcuts) and [docs/adr/README.md](docs/adr/README.md) (design decisions ADR-0001 to ADR-0031). CI: `.github/workflows/tests.yml` (manual `workflow_dispatch`) runs every check below plus the build and both e2e browsers.

## What it is

Tablenox is a **solo, offline-first virtual tabletop** that runs entirely in the browser: no backend, no accounts, no network calls. Users build a game table (boards/sheets, cards, holders/decks, tokens, counters, dice, text labels, automation buttons) and play on it, including roll-and-write: pen, highlighter, eraser and typed text on top of sheets. Games are stored in IndexedDB and can be exported and imported as `.tablenox.zip`.

- **Library** (`#/`): list of games with create, play, edit, rename, duplicate, delete, export and import, plus a built-in sample game.
- **Edit mode** (`#/edit/:id`): build the table. Add objects, open the properties drawer (inspector), resize/rotate with handles, multi-select.
- **Play mode** (`#/play/:id`): play. Drag a card out of a holder (deck), flip cards, roll dice, write on sheets, click automation buttons.
- Edit and Play are **two views of the same saved `Game`**, switched in place. There is exactly one save per game (ADR-0011).

## Data model essentials (`domain/types.ts`)

- `Game` (schema version 1; no migrations, the app is still in testing, so other versions are rejected): `{ id, title, objects: TabletopObject[], annotations, camera, tableColor?, thumbnail?, createdAt, updatedAt, lastPlayedAt? }` (`lastPlayedAt` is set when the game is opened in Play mode: `markPlayed` in `useTableDocument.ts`, shown in the library with `createdAt`; thumbnails are 640 px wide, rendered at ~2× and shrunk in halving steps by `captureThumbnail`).
- `TabletopObject` is a discriminated union on `kind`: `board | image | card | deck | token | counter | die | label | button | bag | checkbox | timer`. Every kind extends `BaseObject`: `position` (**top-left of the unrotated box**, world units), `width`, `height`, `rotation` (degrees about the centre), `zIndex`, `locked`, `visible`, and optional `hoverZoom` (`off|small|medium|large|xlarge`).
- **Holders = `kind: 'deck'`** (ADR-0019; the UI says "Holder", `kindLabel`). A holder is a zone the cards live in: `cards: CardDef[]` (index 0 = **top**; in a spread the right-most / bottom-most card) and `initialCards: CardDef[]` (the definition used by *Gather & reset*; a holder with one is a "deck"). Optional zone fields: `layout` (`stack` default | `spread`, rendering only: `cardSlots`/`cardIndexAt` in `rules.ts`; a spread runs along the long side: a row in a wide holder, a column in a tall one, `spreadsVertically`), `color` (fill), `fillOpacity` (default `DEFAULT_HOLDER_FILL_OPACITY` = 0, i.e. only the outline shows), `strokeColor` (default = `color`), `strokeOpacity` (default `DEFAULT_HOLDER_STROKE_OPACITY` = 0.3), `strokeStyle` (`dashed` default | `solid`), `cardRotation` (holders only: degrees 0–359 the shown cards are turned, set up in Edit mode; `cardTurn` is the extra turn a Rotate step added, cleared by Gather & reset / a Recall step unless it keeps it; always use `cardRotationOf` (sum) / `rotatedBox`; display only, they come out upright), `label` (empty = no text, drawn above or below per `labelPosition`), `alignRotation`, `cardWidth/cardHeight` (size of the cards it owns; use `cardSizeOf`, never the zone size). Other fields: `drawSide` (`keep` = a card comes out as it lies, cards without a stored side lie face down; or always `faceUp` / `faceDown`; use `drawnFaceUp(deck, card)`), `putSide?` (holders: *Cards come in*, the side a card lies once put in; missing / `keep` = as it was; applied by `cardPutInto(deck, card)` in `addCardToDeck`, `mergePileIntoDeck`, `returnPile` and `resetDeck`; a Recall step's `orientation` is applied afterwards and wins), `individualBacks?`, `backColor`, `backAssetId?`. `isPile: true` = a **pile**: a loose stack without a zone, created by dropping a card on a card, removed when empty. Use `isHolder(o)` for "a zone, not a pile". There is no separate holder kind any more.
- **CardDef** (a card inside a holder/pile): `id`, `name`, face (`faceText`/`faceColor`/`faceAssetId?`), its own optional back (`backColor?`/`backAssetId?`), optional `width/height` (only when different from the owning holder's card size), and optional `faceUp`. Holders and piles **keep every card's side** when a card is put in (unless the holder's `putSide` turns it); definitions (`initialCards`) never store one.
- **CardObject** (a card on the table): carries `cardDefId` and `sourceDeckId`. A card definition is **owned by exactly one holder** (the one whose `initialCards` contains it); see `ownerDeckOf` / `homeDeckOf`.
- **Die**: `sides` (4/6/8/10/12/20), `value` (1-based face index), optional custom `faces[]` (label and/or image) that replace `sides`.
- **Token stacks**: `TokenObject.count` (missing = 1, max `MAX_TOKEN_STACK`; use `tokenCount` / `withTokenCount`). `SplitTokens` takes N off into a new token (`splitTokensCommand`; the stack keeps ≥ 1) and stores `sourceId` (root stack) on it; `RecallToken` merges a token back into its source (`tokenSourceOf` / `tokensTakenFrom`). `MergeTokens` joins identical tokens (`sameTokenLook`: shape, colour, image, size), produced by `resolveDrop` via `findTokenTarget`. In Play mode a stack isn't Konva-draggable: `TableCanvas` turns a drag into "take one token" (`token` gesture, like drawing from a deck); the badge (`CountBadge`, `name="deck-handle"`) or Shift+drag moves the stack. Coloured stacks show darkened copies peeking out; image stacks show only the top token and the badge. `TokenObject.shape` is one of `TOKEN_SHAPES` (geometric shapes plus `pawn | meeple | cube | cylinder | diamond | heart`, drawn from `TOKEN_PATHS` in `visuals.tsx`).
- **Bag** (ADR-0020): `BagObject` `{ items: BagItem[] (index 0 = top), color, playMovable? }` holds whole objects (card, pile, token, die, counter, label, image: `bagAccepts`) under their own ids; `BaseObject.bagId` marks objects that were put into / drawn from a bag (what *Return to bag* and Recall use, `bagOf`). Commands `BagPut`, `BagDraw` (`newId` for a token taken off a stack entry), `ShuffleBag`, `RecallToBag`; `resolveDrop` turns a drop on a bag into `BagPut`. Bags are surfaces like holders (`BACKGROUND_KINDS`, `fixedInPlay` via `hasPlayMovable`); Play-mode drag from a bag = `bag` gesture in `TableCanvas` → `drawRandomFromBagCommand`. `bagCount` counts every token of a stack.
- **Checkbox** (ADR-0021): `checked`, `mark` (`check | cross | dot | fill`), `boxShape` (`square | circle | none`), `color`, `boxColor`, `boxFill` (null = transparent). Play mode: not draggable, no action bar, a click toggles it (`toggleCheckbox`), like a button (`clickInPlay` in `ObjectNode`); Edit mode: double-click toggles. The `check` step treats a board as every checkbox on it. New bags have **no name** (`displayName` shows the kind wherever a name is displayed).
- **Timer** (ADR-0028): `label`, `mode` (`countdown | stopwatch`), `duration` (s, max `MAX_TIMER_SECONDS`), `color`, `textColor`, `sound`, run state `elapsedMs` + `startedAt?` (epoch ms, missing = paused; saved, so it keeps running across reloads). Start / pause / reset are commands (`StartTimer` / `PauseTimer` with `at`, `ResetTimer`; a finished countdown restarts on start) via `toggleTimer` / `resetTimer` (`timerToggleCommand`). Derive the display with `timerText` / `timerFinished` (`domain/timer.ts`), never store it. The visual ticks only while running, flashes at 0:00 and beeps once per run; its ▶ / ↺ are `ui-button`s (`onTimer` on `ObjectVisual`). It moves like a counter in Play mode.
- **Button** (automation, ADR-0018): `label`, `color`, `textColor`, `fontSize?` (missing = auto; `fitFontSize` always shrinks the label to fit), `steps: ButtonStep[]` (`move | pick | recall | rotate | flip | shuffle | sort | roll | counter | check | timer`, each with `objectIds`; a holder stands for itself plus what lies on it; a Move takes cards out of holders/piles and pieces out of bags, never moves the container, and can also target a bag; it has `targetIds` (one or more destinations: with several, cards are dealt one to each in turn, `count` each, ADR-0023); Recall sends cards to their bag/holder, tokens to their stack, pieces to their bag, and a bag/stack/deck gathers its own (options for the holders/bags it gathers into: `rotation` reset (default) / keep `cardTurn`, `orientation` (missing = face down), `shuffle`); Rotate on a holder turns its cards (`cardTurn`), never the holder; Flip has `mode` `toggle | faceUp | faceDown | random` (random = 50/50 per card, or per holder/pile as a whole) and optional `count` (only the top N cards of each holder/pile, flipped in place with `FlipDeckCard`, and the first N loose cards; missing = all, a holder flips as a whole with `FlipDeck`); Shuffle also takes bags; Timer has `mode` `start | pause | toggle | reset | restart`, planned with the `now` that `planButton(state, button, random, now)` takes, so a finished countdown restarts on `start`). `planButton` (`domain/buttons.ts`) compiles the steps into one `Batch` by applying each step to a working copy; the UI only calls `runButton(id)` (async: a **Pick** step (`PickStep`: holders / piles, `targetIds`, `orientation`, `choose` `edit` | `run`, missing = `run`) takes cards set up with the step (`choose: 'edit'`: `cards` = card definition ids per holder, chosen in the editor with *Choose cards…* → `chooseStepCards`, from the holder's definition `pickableCards`; only cards still in the holder at that point are taken, no dialog; keep `cards` in step with `objectIds` via `withPickHolders` / `withPickCards`) or asks the player (`run`): then `runButton` uses `planButtonRun`, which stops at the first holder without one (`PendingPick`, `pickKey`), shows `pickManyDialog` for the holder as the earlier steps left it, then plans again from the start with the same seed and `now`; Cancel dispatches nothing; ADR-0030). Sort steps also `reverse`. Editor: `objects/ButtonEditor.tsx` (the *Automations* button comes first in the properties panel and in the Edit-mode action list). Steps are edited in a separate automations drawer (`automationButtonId` in the store, independent of the selection); step objects are picked **only** on the table via the store's `picking` state (clicks toggle, Shift+drag adds, see `pickOnTable`; there is no list menu). `describeStep` always starts a move step with *Move*. In Play mode a click runs a button (it sinks while held); it isn't draggable or selectable there.
- **Assets** (images) live **only** in the `assets` store as Blobs; objects reference them by ID. Use `collectAssetIds` / `remapAssetIds` in `objects.ts` whenever you add an asset field.
- **Annotations** (`InkStroke`, `TextAnnotation`, ADR-0031): without `objectId` they are in world coordinates; with `objectId` they **belong to that sheet** (board / image, `MARK_ANCHOR_KINDS`) and use its own coordinates (origin = top-left of its unrotated box), so they move / turn with it for free. New strokes / stamps / text attach to the topmost visible sheet under them (`anchorStroke`, `placeText`); always hit-test with `strokeHitAt` / `textHitAt` and get a text's screen place with `textWorldPosition`. `applyCommand` stretches a resized sheet's marks (`followResizedSheets`, skipped for `Batch` / `ReplaceTable` so nothing scales twice) and `DeleteObject` removes them; a sheet that isn't on the table (image in a bag) hides them. `InkStroke.straight` = drawn without smoothing (stamps).

## Core architecture rules

1. **All table mutations go through commands.** `useTableStore.getState().dispatch(cmd, { coalesceKey? })` → pure `applyCommand(state, cmd)` in `domain/commands.ts`. The reducer must be pure and immutable, and must return the **same reference for no-ops** (history skips them). Use `Batch` for multi-object changes so they are one undo step. Use `coalesceKey` to merge rapid edits (sliders, nudges, group drags).
2. **Commands that create objects carry their new IDs** (e.g. `DrawCard.cardId`, `MergeCards.pileId`), so replaying a command is a no-op and can't create duplicates.
3. **Randomness is decided outside the reducer** (shuffle order, die value are fields on the command) → the reducer stays deterministic and testable.
4. **Camera, selection, tool, hover and UI prefs are not undoable.** Only `history.present` (objects + annotations) is.
5. **Persistence**: any `revision`/`cameraRevision` change marks the doc dirty → debounced autosave (about 600 ms) overwrites the single game record. UI prefs (`toolbarOpen`, `inspectorOpen`, `palettePinned`, `uiHidden`, `showGrid`, `cameraLocked`, `gridSize`, `snapToGrid`) are saved in `localStorage` (`tablenox.ui`), not in the game. The library thumbnail is captured only when leaving the game (`onStageLeaving`, fired from a layout-effect cleanup in `TableCanvas` before its Stage is detached, plus `pagehide`), not on autosave.
6. **Schema changes**: while the app is in testing there are no migrations; change the schema freely and delete local data. Update `types.ts`, the Zod schema in `schema.ts`, and (for assets) `collectAssetIds`/`remapAssetIds`. Other schema versions are rejected on load and import.
7. **Domain stays UI-free.** Put rules in `domain/` (and test them there). UI files only translate gestures into commands.
8. Dev-only test hook: `window.__tablenoxStore` (ADR-0009); e2e tests read world state through it.

## Interaction model (behaviour that is easy to break)

- **Selection bar** (small black panel) appears **only after a plain left click**, never after a drag (`barObjectId` in the store; `MULTI_BAR` for groups). The **right-click menu** shows *every* action for the current mode, from the same `getObjectActions` / `getGroupActions` list, plus the inline controls and (Edit mode) "Zoom on hover". **Play mode lists game actions only** (draw, shuffle, flip, roll, gather & reset, run…); setup actions (draw side, layout, lock, Movable in Play mode, z-order, duplicate, delete, zoom on hover) are Edit-only, and `L` / `Delete` only work in Edit mode. Objects with nothing to do in Play mode (e.g. boards) get no menu there (`hasObjectControls`).
- **Holder properties panel** (`Inspector.tsx`): `DeckEditor part="list"` = *Card list* (first), split into a *Fronts* subsection (card tools, *Show card list*, the list: one row per run of identical cards (`cardGroups` / `sameCardLook`) with ▲ / ▼ (`moveCardGroup`), the name, the face text (only for cards without a face image: text is never drawn on image cards) and a copies field with − / + (`CopiesInput`; − / + and ↑ / ↓ apply at once, typing commits on Enter / blur; *Set copies for all cards…* below the list = `setAllCardCopies`) (`setCardCopies`: copies are separate `CardDef`s with their own ids, so drawing / recall / reset need nothing special); editing or removing a row applies to all its copies) and a *Backs* subsection below it (back colour/image, individual backs + *Set backs from images*, *Use fronts as backs* via `withFrontAsBack`); *Holder* = the zone (label, layout, card alignment (`spreadAlign`, spreads only: left / center / right, or top / center / bottom when it runs down; missing = center), card rotation, align rotation), then `DeckEditor part="settings"` = *Cards* (card size, `DrawSideField`, *Cards come in* (`putSide`), shuffle, gather & reset). The zone's look (`HolderLookFields`: colour, opacity, stroke colour / opacity / style) is in the *Object* section (`CommonFields`), below *Rotation angles*.
- **Rotation angles**: `BaseObject.rotations?` (multiples of 45°; missing = `DEFAULT_ROTATIONS` 0/90/180/270; cards and piles inherit their deck's via `effectiveRotations`, like hover settings). The Rotate action (`pushRotate` in `objectActions.ts`, label "Rotate to N°") and `R` / `Shift+R` call `rotateStep` → `nextRotation` (next allowed angle clockwise / anticlockwise; null = can't turn, so one angle disables rotation). Edit-mode Transformer handles, the *Rotation°* field and automation Rotate steps are not limited. Dice have no setting (`R` rolls). Piles only show *Cards come out*, *Shuffle* and *Return cards to holders* (their own back fields are never used: pile cards keep their own or their owner's look). Cards and piles show `HolderLinks` (*Go to <holder>*, via `focusObject`; `pileHolders`, `homeDeckOf`). In Play mode a pile's menu has *Return cards to their holders* (`ReturnPile`) and a card's *Return to holder*.
- **Locked** objects can't be dragged in either mode. Dragging them pans the camera. **Boards and holders are fixed in Play mode** (`fixedInPlay`: dragging them pans, like the table surface) and move freely in Edit mode, unless `playMovable` is set ("Movable in Play mode" in the properties panel / Edit-mode right-click menu). New boards are not locked.
- **Play-mode holders aren't draggable**: pressing on a card in a holder (its top card when stacked, any card when spread: `cardIndexAt`) and dragging draws that card and hands the pointer to it. Dragging the black **count badge** (`name="deck-handle"`, only shown with 2+ cards) lifts the **whole stack** out as a new pile (`TakeStack` / `takeStackCommand`; one card is just drawn) and hands the pointer to it; the holder stays put. Pressing elsewhere on the zone (or Shift+drag) moves the holder only if it is movable in Play mode, otherwise it pans. A pile's badge or Shift+drag moves the pile. Double-click turns over the top card in place (`FlipDeckCard`; in a spread the double-clicked card), in both modes.
- **Edit-mode holders** show their cards exactly as in Play mode, but the outline is drawn at least `EDIT_MIN_STROKE_OPACITY` (0.85) opaque so it stands out over the grid, and a holder with its own card list shows `Deck (N cards)` (N = `initialCards.length`) below the zone (`name="deck-info"`, under the label when that is below).
- **Spread holders take dropped cards where they land**: `resolveDrop` adds `index` to `AddCardToDeck` / `MergePileIntoDeck` (`spreadInsertIndex`: after every card whose middle is before the drop point along the spread's axis). While dragging, `ObjectNode` stores it as `dropIndex` next to `dropTargetId`, and `DeckVisual` opens a gap there (`spreadLayout(objects, deck, gapAt)`, `name="drop-gap"`). Stacks always take cards on top. A stack of 2+ cards draws a single thin edge under its top card, whatever its size.
- **Drops** (`rules.ts › resolveDrop`): a card dropped on a holder or pile → `AddCardToDeck` (in Edit mode on a holder it also joins that holder's definition). On a card → `MergeCards` (new pile). A **pile** dropped on a holder/pile → `MergePileIntoDeck` (all its cards go on top, in order). Other pieces dropped on a holder only take its rotation (`alignRotation`). Holders and boards just move. **Shift** = free placement. While dragging, the target (holder, pile or card) fades and gets a yellow outline (`dropTargetId`, `findHoverTarget`).
- **Picked-up look** (Play mode only): `ObjectNode` tilts (+3°) and scales (×1.04) an inner `lift` group while dragging and renders a blurred, blackened copy of the object as its shadow (Konva can't shadow whole groups). Edit-mode drags have no effect. Don't put `rotation`/`scale` props on the `lift` group; they are animated with tweens.
- **Card identity is preserved**: a card put into a foreign holder keeps its own size and back (`resolveCardLook`, ADR-0016) and the side it had. Card size comes from the owning holder's `cardWidth/cardHeight` (`cardSizeOf`), so resizing a holder's zone never resizes its cards.
- **Holder actions**: draw 1, draw N from top/bottom (prompt; several cards come out as **one pile** next to the holder, in deck order: `DrawCards`), pick card(s) (`pickManyDialog` in `uiStore` shows every card, fronts or backs (`cardPickItems`), several can be selected; the single-click `pickDialog` chooses a die face, `pickDieFace`; `drawPickedCardsCommand` draws one card, or several as one pile in holder order via `DrawCards.cardIds`), sort (one menu entry with `children`: original order / name / reverse, `sortDeck`; the context menu expands an entry's `children` below it), shuffle (`S`; any shuffle, also from an automation, plays a short riffle: the store's transient `shuffled` (`shuffledBy`) drives a `Konva.Animation` in `ObjectNode`), flip all cards (reverses the order and turns every card over, `F`), cycle "cards come out" (as they lie → face up → face down), Edit-mode menu-only cycle "cards go in" (`cyclePutSide`, holders only), stack / spread out, Gather & reset (when it has a definition). Card actions are hidden while it is empty.
- **Clicks never roll dice** (ADR-0014): roll with double-click, the bar, the menu or `R`. Double-clicks are detected manually (`doubleClick.ts`) because Konva fires `dblclick` for left+right click pairs.
- **Multi-select**: Edit mode: Ctrl/Shift+click, Shift+drag a selection box (plain drag when the camera is locked), `Ctrl+A`. Play mode: only the selection box (Shift+drag, or plain drag with the camera locked; also when it starts on a fixed surface), which selects only `movableInPlay` objects; no group bar/menu there, and switching to Play mode clears a multi-selection. The Konva Transformer is attached to every selected unlocked node (Play mode: without resize/rotate handles), so dragging one moves all of them (Konva behaviour); each node's drop is a plain move with a shared coalesce key. In Play mode a member that isn't Konva-draggable (pile, token stack, movable holder/bag) starts the group drag itself (`group` gesture in `TableCanvas`).
- **Input precedence** (ADR-0006): the wheel always zooms about the cursor. Pan with an empty-table drag, the Pan tool, Space+drag or middle-drag. With Pen/Eraser/Text/Stamp active, objects aren't draggable. Eraser radius is in screen px; pen width is in world units. The Stamp tool (`M`) adds a stroke on click / tap (`handleClick`), with a ghost preview (`stamp-ghost`). The eraser's hidden-while-erasing set is the store's `erasingIds` (sheets render their own marks).
- **Snap to grid** (Edit mode, `ui.snapToGrid`, `G`): `ObjectNode`'s `dragBoundFunc` snaps the dragged node (`snapPosition`, Shift = free; the Transformer moves the rest of a selection by the same amount), `TableCanvas`'s `boundBoxFunc` snaps dragged edges of unrotated, non-`keepRatio` boxes, `addObject` places new objects on the grid and arrow keys move one grid step. `Grid` draws `ui.gridSize`.
- **Align & distribute**: group-menu entries with `children` (`getGroupActions`, `ALIGN_MODES`) and buttons in the Inspector's multi-selection panel → `alignObjects` / `distributeObjects` in `actions.ts`.
- **Holder rendering**: `DeckVisual` subscribes only to the decks owning its cards (`ownerDecksById` + `useShallow`); don't subscribe visuals to the whole `objects` array.
- **Touch** (ADR-0022): Konva sends `tap`/`dbltap` instead of `click`/`dblclick`; every click handler needs a tap twin (the Stage shares `handleClick`). Two fingers pinch / pan (`pinchBy`), a long-press opens the right-click menu (`openMenuAt`), except on a card with an effective hover zoom (loose, the card under the finger in a holder, or a pile's top card: `pressPreviewOf`): that shows the enlarged preview while the finger stays down (`pressPreviewId` + `pressPreviewCardId` in the store, shown at once by `HoverPreview`, cleared when the last finger lifts); both suppress the taps of the fingers involved (`canvas/touch.ts`: check `tapsSuppressed()` in new tap handlers). Panels below the top bar use `var(--hud-top-h)` instead of a fixed offset.
- **Hover zoom** is per object (no global toggle). Cards without their own setting inherit their home deck's; holders and piles without one inherit from the deck owning the card shown (`effectiveHoverZoom(state, o, cardId)`). Previews show a card as it lies (face or back), upright unless `hoverRotate` (*Zoomed view*, inherited the same way: `effectiveHoverRotate`) turns them like the object (`hoverRotationOf`: rotation plus a holder's card rotation); a spread previews the card under the mouse (`hoverCardId` in the store).
- New holders are gray, unlabelled, stacked, draw cards as they lie, and are a card plus `HOLDER_MARGIN` (6) on each side so the zone shows around the cards (`createObject('deck')`); Add → *Deck* is the very same holder filled with a standard 52 (lying face down). The default table colour (no `tableColor`) is grey `#3b3f46` (`--felt`).

## Conventions

- Keep changes small and focused. Comment only where the code isn't obvious. Prettier formatting (run `--write` on touched files).
- Each user-visible behaviour change should come with: a unit test (domain) and/or an e2e test, plus updates to `HelpDialog.tsx`, `README.md` (features + shortcut table), and an ADR entry in `docs/adr/README.md` for notable design decisions. `IMPLEMENTATION_PLAN.md` has a revision log (it is git-ignored, like the original `solo_tabletop_design_spec.md`).
- Icons: add SVG paths to the `paths` map in `components/Icon.tsx`.
- Every user-facing string is English. No external network requests, analytics or third-party card art (text-based faces, ADR-0010).
- Deployment target: static hosting (Cloudflare Pages); hash routing means no rewrite rules are needed.
